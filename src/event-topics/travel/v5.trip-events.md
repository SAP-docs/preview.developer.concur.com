# Trips Event v5

## <a name="overview"></a>Overview

The Trips v5 API provides clients and authorized partners access to trip data through lifecycle events on the public topic `public.concur.travel.trips`. Subscribers receive events when a trip is created, updated, deleted, or anonymized. For created and updated events, use the `facts.hrefs.v5` link to retrieve the current trip record from the [Trips v5 API](/api-reference/travel/trips-v5/v5.trips.html).

The Trips v5 event topic is the successor to the v4 Itinerary Event topic, `public.concur.travel.itinerary`. The topics have independent ESS subscriptions.

To subscribe to these events, follow the steps described in the [Event Subscription Service v4](/api-reference/ess/v4.event-subscription.html) documentation.

## <a name="limitations"></a>Limitations

Access to this documentation does not provide access to the subscription or the Trips v5 API.

Trips v5 events are available in the US2, EU2, and APJ1 data centers. The event topic and API subscription must be configured for the applicable company and partner application.

## <a name="scope-usage"></a>Scope Usage

Name|Description
---|---
`events.topic.read`|Access the Event Subscription Service and manage event subscriptions.
`travel.trip.read`|Subscribe to the Trips v5 event topic and retrieve the public trip view from the Trips v5 API.

The Trips v5 response is additionally filtered by any named trip scopes granted to the application. See the [Trips v5 API reference](/api-reference/travel/trips-v5/v5.trips.html#scope-usage) for the booking, location, pricing, and public trip scopes.

## <a name="event-delivery"></a>Event Delivery

ESS delivers events to registered partner webhook endpoints. Event delivery is filtered using the partner configuration associated with the company:

* The `groups` array contains the partner configuration IDs whose criteria matched the trip, followed by the company ID catch-all group.
* ESS delivers the event to a subscription when its configured group intersects the event's `groups` array.
* A deleted event is published without retrieving the deleted trip and is routed to all partner configurations for the company because the deleted trip is no longer available for filter evaluation.

Partners should make webhook processing idempotent. Use the event `id` and `correlationId` for event tracking and troubleshooting.

## <a name="events"></a>Events

All events under topic `public.concur.travel.trips` are listed below.

Event type|Description|Trip link
---|---|---
`concur.travel.trips.Trip.Created.v1`|Published when a new trip is created.|The `facts.hrefs.v5` link is included.
`concur.travel.trips.Trip.Updated.v1`|Published when an existing trip is modified.|The `facts.hrefs.v5` link is included.
`concur.travel.trips.Trip.Deleted.v1`|Published when an existing trip is permanently deleted.|No trip link is included.
`concur.travel.trips.Trip.Anonymized.v1`|Published when a trip is anonymized for GDPR erasure.|No trip link is included.

## <a name="retrieve-trip"></a>Retrieve Trip Data

For `Trip.Created.v1` and `Trip.Updated.v1` events:

1. Receive the event at the configured webhook.
2. Read the URL in `facts.hrefs.v5`.
3. Use a Company-level access token with the required Trips v5 scope.
4. Send a GET request to the URL.

~~~http
GET https://us2.api.concursolutions.com/travel/v5/trips/{tripID}
Accept: application/json
Authorization: Bearer <JWT Token>
~~~

Do not call the Trips v5 API for `Trip.Deleted.v1` or `Trip.Anonymized.v1` events. These events do not include `facts.hrefs` because the trip resource is no longer retrievable. Remove or anonymize the corresponding partner record as appropriate.

## <a name="schema"></a>Schema

### <a name="schema-event"></a>Schema for Event

Name|Type|Format|Description
---|---|---|---
`id`|`string`|UUID|Unique identifier of the event.
`correlationId`|`string`|UUID|Correlation identifier used for distributed tracing.
`topic`|`string`|-|`public.concur.travel.trips`.
`subTopic`|`string`|UUID|Trip UUID used as the event subtopic.
`eventType`|`string`|-|Versioned lifecycle event type.
`type`|`string`|-|Event type carried by the published event envelope.
`specVersion`|`string`|-|Event specification version. `2.0`.
`version`|`string`|-|Event schema version. `1.0.0`.
`timeStamp`|`string`|RFC 3339|UTC time when the event was issued.
`groups`|`array`|UUID strings|Partner configuration IDs matched by the event filters, plus the company ID catch-all group.
`facts`|`object`|[Facts Schema](#schema-facts)|Trip identifiers and, when available, the versioned trip resource link.

### <a name="schema-facts"></a>Schema for Facts

Name|Type|Format|Description
---|---|---|---
`userId`|`string`|UUID|Traveler UUID.
`companyId`|`string`|UUID|Company UUID.
`tripId`|`string`|UUID|Trip UUID.
`hrefs`|`object`|Map of URLs|Version-keyed map of trip resource links. For retrievable trips, `v5` contains the Trips v5 URL.

The `hrefs` property is omitted for deleted and anonymized events.
